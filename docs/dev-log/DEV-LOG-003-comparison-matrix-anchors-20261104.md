## 决策依据

### ① 为何维度固定为七维

外部模板 L32 明确「维度逐行固定（七维）；选项列按需增删」；L14 说明形态定义以 `SPEC_PROCESS.md` 为权威源。自拟维度会与外部模板漂移，且无法解释为何缺少某一维。本仓因此逐行同构，仅把模板的「可维护性」在本节写作「维护（可维护性）」，并注明正式名。

### ② 为何要求外部证据锚点

用户指令要求「找到外部证据锚点」。与 §11.2 的 T1-T4 分级对接后，落成三条可核验约束：每方案 ≥2 个外部 T1/T2 锚点、覆盖 ≥3 个维度、每个维度行至少 1 个方案有外部锚点。这三条是对抗「单源写成共识」与「凑锚点」的最低结构，而不是质量评分。

### ③ 为何只对 Type-1 启用矩阵

外部规范 L453-L458 与模板 L18-L26 均规定：Type-2（有回退点 / 无常驻副作用）先做再改，不启动矩阵。若对可逆决策也强制七维取证，会制造分析瘫痪（模板 L77）。本仓沿用该判据，并要求在矩阵内逐项勾选与写判定依据。

### ④ 为何要求声明「短期 / 长期」的时间口径（本仓增补）

外部模板七维含「短期 / 长期」，但未定义时间窗。若不声明口径，同一矩阵内不同格子会使用不同时间跨度，导致结论不可比、且易被 criteria gaming（模板 L78）。因此本仓在 11.8.3 增加前置声明硬约束：短期与长期须以可机械识别的时间窗或迭代边界定义，且矩阵内固定、不得逐格改动。**该条为本仓增补，不是外部模板要求**，已在此显式标注来源。

### ⑤ 为何不新增门禁

模板 L82 与 `SPEC_PROCESS.md` L467 均声明这是过程性约定，无门禁、无校验器；可机械化的只有「格是否齐全 / 证据等级是否非空 / 触发条件是否存在 / 引用是否完整」。本批同样只写纪律，不改任何脚本、依赖或 CI。
