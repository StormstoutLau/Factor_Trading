### 1.2 当前引擎核心能力

**功能维度:**
- ✅ 因子处理流水线: Winsorize → Fill → Neutralize → Standardize → Combine
- ✅ 组合优化: 等权重 / 最小方差 / 均值方差 / 风险平价
- ✅ 执行模拟: VWAP / TWAP / Close 多种价格类型
- ✅ 交易成本: 佣金 + 印花税 + 滑点
- ✅ Walk-Forward 分析: Rolling / Expanding + Purge Gap
- ✅ Guard Pipeline: 5 种风控检查 (持仓上限 / 回撤止损 / 冷却期 / 白名单 / 换手率)
- ✅ EventLog: JSONL 持久化 + 内存 Ring Buffer
- ✅ 插件系统: Registry + Factory + 自动注册
- ✅ Brinson 归因: 行业配置 + 选股 + 交互效应
- ✅ 五维风控: 基本面 / 行业 / 宏观 / 资金流 / 情绪

**设计理念:**
- V1: 经典 Loop 模式，setup → run → 逐日迭代
- V2: 依赖注入 (DI)，可 Mock 各模块，"Lego" 风格组装
- V3: 向量化矩阵方法，NumPy 批量计算替代逐日 Loop

| **Stars** | — | 15k+ | 18k+ | 4k+ | 16k+ | 5k+ |

### 2.2 各维度详细对比

#### 2.2.1 回测执行性能

| 场景 | Factor Trading V1/V2 | Factor Trading V3 | Backtrader | Zipline | VectorBT | Qlib |
|------|:---:|:---:|:---:|:---:|:---:|:---:|
| 500 股票 × 5 年 | ~5-15s | **~0.5-2s** | ~30-60s | ~10-20s | **~0.1-0.5s** | ~5-15s |
| 3000 股票 × 10 年 | ~60-120s | ~5-15s | 极慢 (O(n²)) | ~60-120s | **~1-3s** | ~30-60s |
| 内存占用 (大数据) | 中 | 高 (全矩阵) | 中 | 高 | 高 (全矩阵) | 中 |
| 并行化 | ❌ 无 | ❌ 无 | ❌ 单线程 | ❌ 单线程 | ✅ Numba JIT | ✅ 多进程 |

**当前瓶颈:**
- V1/V2 逐日 Loop 是 Python 级循环，5000 股票 × 2500 天 = 1250 万次迭代，每轮 Python 函数调用开销大
- V3 向量化解决了 Loop 问题，但全矩阵内存占用 O(股票数 × 天数)，大数据集可能 OOM
- **三引擎均未利用 Numba JIT 编译、多线程/多进程并行**

#### 2.2.2 容错与数据一致性

| 能力 | Factor Trading | Backtrader | Zipline | VectorBT |
|------|:---:|:---:|:---:|:---:|
| 数据校验 (Config) | ✅ Pydantic (V2) | ❌ 基本无 | ✅ Pipeline Domain | ❌ 基本无 |
| 缺失数据处理 | ✅ 多策略填充 | ⚠️ 手动 | ✅ Pipeline 自动 | ❌ NaN 直接报错 |
| 停牌/除权处理 | ❌ **缺失** | ⚠️ 需手动 | ✅ 内置 | ❌ 需手动 |
| 涨跌停处理 | ⚠️ 因子层有 | ❌ 无 | ❌ 无 | ❌ 无 |
| 未来函数防护 | ✅ Walk-Forward | ❌ 无 | ✅ Pipeline | ❌ 无 |
| 交易校验 (Guard) | ✅ 5 层 Guard | ❌ 无 | ❌ 无 | ❌ 无 |
| 订单状态机 | ❌ **缺失** | ✅ 完整状态机 | ✅ 订单追踪 | ❌ 无 |
| 部分成交 | ❌ **缺失** | ✅ 支持 | ✅ 支持 | ❌ 无 |
| 回滚/断点续跑 | ❌ **缺失** | ❌ 无 | ❌ 无 | ❌ 无 |

**当前短板:**
- **订单生命周期管理缺失**: 无 `PENDING → SUBMITTED → PARTIAL → FILLED → CANCELLED` 状态机，假设所有订单全部成交
- **停牌/除权/退市处理缺失**: 数据层未自动处理复权因子，停牌股票可能被错误买入
- **部分成交模拟缺失**: 实际市场流动性受限时，大单可能无法全部成交
- **无断点续跑**: 回测中断后无法从 checkpoint 恢复

#### 2.2.3 设计理念对比

| 理念 | Factor Trading | Backtrader | Zipline | VectorBT | Qlib |
|------|------|------|------|------|------|
| **策略接口** | 配置驱动 (Config) | 类继承 (Strategy) | 函数式 (initialize/handle_data) | 函数式 (indicator) | 配置 + ML 模型 |
| **模块解耦** | ✅ DI 接口 | ❌ 强耦合 | ⚠️ Pipeline 层解耦 | N/A (单一职责) | ✅ 分层解耦 |
| **可扩展性** | ✅ 插件系统 | ✅ Observer/Analyzer | ✅ Pipeline | ⚠️ 有限 | ✅ 模块化 |
| **可测试性** | ✅ DI Mock | ❌ 难 Mock | ⚠️ 中等 | ✅ 纯函数 | ✅ 模块化 |
| **多资产支持** | ❌ 仅股票 | ✅ 股票/期货/外汇 | ✅ 股票/期货 | ✅ 泛用 | ❌ 仅股票 |
| **实时交易** | ❌ 不支持 | ✅ Live Trading | ✅ Live Trading | ❌ 不支持 | ❌ 不支持 |
| **参数优化** | ❌ 无 | ✅ 内置优化器 | ❌ 无 | ✅ 网格搜索 | ✅ 超参搜索 |

**当前优势:**
- **DI 设计** 领先于 Backtrader/Zipline，达到 NautilusTrader 级别的模块化
- **Guard Pipeline** 是独有功能，Zipline/Backtrader 均无前置风控链
- **插件系统** 架构优雅，超越所有对比框架的扩展方式

**当前短板:**
- **不支持多资产类别** (期货/期权/外汇)，限制应用场景
- **无实盘交易接口**，无法从回测无缝切换到实盘
- **无参数网格搜索/优化**，需手动调参

## 三、可提升方向 (按优先级排序)

### 🔴 P0 — 核心缺失

#### 3.1 订单状态机 + 部分成交模拟
**现状**: 所有订单假设全部成交，无撤销/拒绝/部分成交
**对标**: Backtrader 的完整 Order 状态机
**方案**:
```python
class OrderStatus(Enum):
    CREATED = "created"
    SUBMITTED = "submitted"
    PARTIAL = "partial"
    FILLED = "filled"
    CANCELLED = "cancelled"
    REJECTED = "rejected"

class Order:
    order_id: str
    status: OrderStatus
    filled_qty: float
    avg_price: float
    # 支持限价单/市价单/止损单
    order_type: OrderType
    limit_price: Optional[float]
```

#### 3.2 停牌/除权/退市处理
**现状**: 数据层未处理公司行为 (Corporate Actions)
**对标**: Zipline 的 `adjustments` 模块
**方案**: 在 [DataManager](file:///f:/Coding/Factor_Trading_v3.0/core/data.py) 中增加:
- 复权因子自动乘除
- 停牌日自动跳过
- 退市日自动平仓

#### 3.3 Numba JIT 加速
**现状**: V3 用 NumPy 向量化，但未用 Numba 编译
**对标**: VectorBT 的核心计算全部 `@njit` 编译
**方案**:
```python
from numba import njit

@njit(parallel=True)
def _compute_portfolio_returns(weights, returns, price_matrix):
    """编译级加速的组合收益计算"""
    ...
```

### 🟡 P1 — 重大增强

#### 3.4 多资产类别支持
**现状**: 仅股票 (A 股)
**对标**: Backtrader 支持 Stock/Future/Forex/Option
**方案**: 在 [core/interfaces.py](file:///f:/Coding/Factor_Trading_v3.0/core/interfaces.py) 中增加:
```python
class AssetType(Enum):
    STOCK = "stock"
    FUTURE = "future"
    OPTION = "option"
    FOREX = "forex"
    CRYPTO = "crypto"
```

#### 3.5 断点续跑 (Checkpoint)
**现状**: 回测中断后无法恢复
**方案**: 利用已有 [EventLog](file:///f:/Coding/Factor_Trading_v3.0/core/event_log.py) 的 JSONL 存储:
```python
class CheckpointManager:
    def save(self, state: EngineState, path: str) -> None: ...
    def restore(self, path: str) -> EngineState: ...
```

#### 3.6 参数网格搜索
**现状**: 无自动参数优化
**对标**: Backtrader 内置 `optstrategy`，VectorBT 的 `grid_search`
**方案**: 新增 `core/optimizer.py`:
```python
class ParamGridSearch:
    def search(self, engine_cls, param_grid, metric="sharpe") -> pd.DataFrame:
        """遍历参数组合，按指标排序"""
```

#### 3.7 实盘交易桥梁
**现状**: 仅回测，无实盘
**对标**: Backtrader 的 `Cerebro` 支持 `broker.set_cash()` 连接实盘
**方案**: 抽象 `Broker` 接口，分别实现 `SimulatedBroker` 和 `LiveBroker`:
```python
class IBroker(ABC):
    @abstractmethod
    def submit_order(self, order: Order) -> str: ...
    @abstractmethod
    def get_positions(self) -> dict[str, Position]: ...
```

### 🟢 P2 — 体验优化

#### 3.8 技术指标库
**对标**: TA-Lib 集成，内置 100+ 指标
**方案**: 在 `core/indicators.py` 中提供常用指标 (MA/RSI/MACD/Bollinger/ATR)

#### 3.9 策略模板库
**对标**: Backtrader 的 Strategy 基类继承体系
**方案**: 在 `strategies/` 下提供模板:
- 双均线策略
- 动量策略
- 均值回归策略
- 网格交易策略

#### 3.10 内存优化
**现状**: V3 全矩阵加载，大数据 OOM
**方案**:
- 分块计算 (Chunked Processing)
- 内存映射文件 (mmap)
- Pandas `chunksize` 分批读取

## 四、总结

### 当前引擎定位

| 维度 | 评分 | 说明 |
|------|:---:|------|
| 功能完整度 | ⭐⭐⭐⭐ | 因子/优化/风控/归因/Agent 体系完整，超越多数框架 |
| 架构设计 | ⭐⭐⭐⭐⭐ | DI + 插件 + Guard Pipeline 达到一流水平 |
| 执行性能 | ⭐⭐⭐ | V3 向量化已接近 VectorBT，但缺 Numba 加速 |
| 容错健壮性 | ⭐⭐⭐ | Guard Pipeline 优秀，但缺订单状态机/停牌处理 |
| 生态丰富度 | ⭐⭐ | 缺指标库/策略模板/社区扩展 |
| 生产就绪度 | ⭐⭐ | 缺实盘桥梁/断点续跑/多资产 |

### 独特优势 (vs 其他框架)
1. **Guard Pipeline** — 独有前置风控链，NautilusTrader 级别
2. **DI 可测试架构** — Backtrader/Zipline 不具备
3. **Multi-Agent 系统** — 全市场唯一集成了 Agent 的回测框架
4. **五维风控 + 全球传染** — 学术级风控模型
5. **Walk-Forward + Purge Gap** — 对标 Lopez de Prado 方法论

### 核心差距 (vs 其他框架)
1. **订单状态机** — 无部分成交/撤销/拒绝
2. **停牌/除权** — 公司行为处理缺失
3. **Numba 加速** — VectorBT 性能 10x 差距
4. **多资产** — 仅股票 vs Backtrader 全品类
5. **实盘桥梁** — 无法从回测切换实盘
6. **生态** — 无指标库/策略模板/社区

### 建议优先路线
```
P0 (本月): 订单状态机 + 停牌处理 + Numba JIT
P1 (下月): 多资产 + Checkpoint + 参数搜索
P2 (Q3): 技术指标库 + 策略模板 + 内存优化
```
